## 2. 我方编制沿革（A）——"旅"与"师"的关系

- 解放战争**前期**：野战军 → 纵队 → **旅**（每旅辖 3 个团，是基本战术兵团）→ 团 → 营 → 连 → 排 → 班。
- **1948-11-01** 中央军委颁发《关于统一全军组织及部队番号的规定》：纵队改称**军**，师和旅统一称**师**；军以上设兵团、野战军两级；军以下一般按**三三制**（军辖 3 师、师辖 3 团）；团以上番号全军统一排序；野战部队 / 地方部队 / 游击部队分类。
- 1949-01-15 各大野战军改按序数排列（第一至第四野战军）；1949-02 起各野战军陆续完成改名，军配直属炮兵团、工兵团及警卫分队。
- 结论：**玩家若称"师长"且下辖 3 个团，史实时间点应在 1948-11 之后；此前同一级单位称"旅"，隶属纵队。** 游戏在编制说明中明示这一沿革，1947 年剧本把该级标为"旅（后改称师）"，1948-11 后剧本标为"师"。
- 来源：`www.mod.gov.cn/gfbw/gfjy_index/js_214151/4865014.html`（国防部《军队中的旅是怎样演变的》）；`m.people.cn/n4/2017/0506/c45-8902343.html`（人民网）；`theory.people.com.cn/BIG5/n/2014/0825/c40538-25534648.html`（人民网理论频道）；`www.xiancn.com/zt/content/2021-02/01/content_3675976.htm`（西安新闻网·党史上的今天）。

## 3. 十大军事原则（A）——1947-12《目前形势和我们的任务》

1. 先打分散和孤立之敌，后打集中和强大之敌。
2. 先取小城市、中等城市和广大乡村，后取大城市。
3. **以歼灭敌人有生力量为主要目标**，不以保守或夺取城市和地方为主要目标。
4. **每战集中绝对优势兵力（两倍、三倍、四倍，有时甚至五倍或六倍于敌）**，四面包围敌人，力求全歼，不使漏网；力求避免得不偿失的消耗战。
5. 不打无准备之仗，不打无把握之仗。
6. 发扬勇敢战斗、不怕牺牲、不怕疲劳和连续作战的作风。
7. **力求在运动中歼灭敌人**，同时注重阵地攻击战术。
8. 攻城：守备薄弱坚决夺取；中等守备相机夺取；守备强固则等候条件成熟。
9. **以俘获敌人的全部武器和大部人员补充自己，我军人力物力的来源主要在前线。**
10. 善于利用两个战役之间的间隙休息和整训部队。

- 来源：`www.mod.gov.cn/gfbw/fgwx/16139866.html`（国防部）；`www.cctv.cn/military/tactics/2003-12-26/11661.shtml`（央视网全文）；`cpc.people.com.cn/n1/2022/0830/c443712-32515125.html`（中国共产党新闻网）。

## 4. 敌方编制与装备（C 为主，A 未见同等细目）

- 1946 年"三十五年编制"：原**军**改为**整编师**，原**师**改为**整编旅**；整编旅仅 2 个实编步兵团 + 1 个补训团（仅骨干）；甲种军 → 3 旅 6 团制整编师，乙种军 → 2 旅 4 团制整编师。名为"师"，实为军级规模。
- 装备分美械 / 半美械 / 日械 / 国械四类；重炮、装甲多上调至绥靖区或总部，战前临时配属，造成协同迟缓；东北、华北一度仍用军—师—团旧番号，两套体系并行。
- 结构性弱点：整编旅两团制一线兵力薄、补训团依赖稳定后方、临时编组的"整编军"指挥权松散、派系保存实力。1948 年秋南京军事会议决定恢复军、师番号并固定兵团建制。
- 参考数字（**来源之间不一致，仅用于设定参数区间，不写入游戏史实陈述**）：整编第 74 师约 3 万余人、全副美械、3 旅 6 团，1947-05 孟良崮战役被华东野战军围歼。
- 来源：`mp.weixin.qq.com/s?__biz=MzU2MzU0NTIwNQ==&mid=2247486915...`（《1946 年国军部队编制大调整》，二手整理）；`baike.baidu.com/item/国民革命军整编第七十四师`；`baike.baidu.com/item/国民革命军第七十四军`。

## 5. 战术与作战样式（A）

- **近迫作业 / 交通壕攻击**：锦州、碾庄、双堆集、小张庄、陈官庄普遍使用。"以地堡对地堡、以战壕对战壕"，交通壕逐夜推进数十米，逼近敌前沿数十米后猝然发起冲锋，抵消敌远战火力、大幅减少开阔地冲击伤亡。
- **弥补炮火不足**：炸药抛掷筒（"飞雷炮"）、抵近射击。
- **先打弱敌、后打强敌，攻其首脑、乱其部署**：碾庄围歼黄百韬兵团时先打第 44 军、第 100 军，再打第 25 军、第 64 军。
- **穿插分割、围点打援、口袋阵、阻击**：五路大军合围碾庄；以一部阻援、一部围歼。
- **夜战、近战、连续作战**：连排干部伤亡后由班长、战士、司号员、卫生员自动代理，边打边编组。
- 刘伯承总结双堆集："以运动战始，以阵地战终；以消耗敌人始，以围歼敌人终。"
- 代价：淮海战役解放军牺牲 3.1 万余人、伤 13.6 万人。**设计上须体现胜利有代价，不渲染血腥。**
- 来源：`www.81.cn/ss/2022-06/29/content_10167436.htm`（中国军网《淮海战役：我军何以步步占先》）；`dangshi.people.com.cn/n1/2019/0220/c85037-30806926.html`（人民网党史《王秉璋创行新战术》）；`dangshi.people.com.cn/n1/2016/0811/c85037-28628679.html`（人民网党史·小张庄战斗）；`fsdz.lncourt.gov.cn/article/detail/2023/09/id/7554238.shtml`（碾庄战斗碑文敬读）。

## 6. 指挥通信（A/B）——命令延迟机制的直接依据

- 淮海战役期间中央军委发往前线的电报 500 余封，其中毛泽东亲笔电文 74 封；总前委电台为手摇发电机供电的无线电设备。
- "暗语通信"：简短指令数秒可达；再用**司号**按师—团—营—连逐级下传，顺利时"停止待命"命令不到十分钟传达到连。（B：116 师通信工作回忆）
- 运动战中"自下而上"架设有线电话，避免指挥部转移导致线路作废；电话线易被炮火炸断，中断时靠**通信员徒步**传送，延误可达一小时以上。
- **小喇叭**是连以下小分队夜间战斗指挥与战斗小组协同工具。
- 电台天线被炸断时战士用手扯住两端电线完成特急电报收发；雷电、敌机干扰影响收发。
- 来源：`www.81.cn/yljnt_208627/lsda_208656/16453342.html`（中国军网《淮海战役指挥通信》）；`v.people.cn/n1/2022/0415/c437379-32400400.html`（人民视频·鲁西南战役电报）；`www.wphoto.net/qianbei/article/ts/show/articleid/10810`（116 师通信回忆，B）。

## 7. 支前与后勤（A）

- 淮海战役：五省出动支前民工 **543 万人**，担架 20 多万副、大小车 88 万余辆、担子 30 多万副、牲畜 76 万多头、船只 8539 艘；运送粮食 9.6 亿斤（约 2.15 亿公斤）、弹药 1460 多万斤（约 730 万公斤）。543 万仅指常备随军民工，含后方生产群众则更多。

## 8. 政治工作与兵员补充（A）

1. 游戏**不改写**历史结论、战役胜负与宏观进程；剧本为师级局部战斗的**教学推演**，不是战役复刻。

## 12. 开放高程数据与真实地形图（v0.4）

用户提出放弃 2.5D、改用**基于开放地图数据的真实地形图，二维平面 + 等高线**。因此地形不再程序生成，改为由真实高程数据派生。

### 12.1 数据集

| 项 | 内容 |
|---|---|
| 数据集 | `aster30m` = **NASA / METI ASTER Global DEM（ASTER GDEM）**，约 30 m 全球数字高程 |
| 分辨率 / 覆盖 | 约 30 m（1 角秒）；全球覆盖，三个战区（32–41°N）均在内 |
| 原始来源 | NASA LP DAAC / ASTER GDEM `https://asterweb.jpl.nasa.gov/gdem.asp`（NASA/METI 公有领域开放高程数据） |
| 采集通道 | Open Topo Data 公共高程 API `https://api.opentopodata.org/v1/aster30m`；数据集列表与限制见 `https://www.opentopodata.org/` |
| 接口限制 | 100 点/请求、1 请求/秒、1000 请求/日；**实测 40 点以上请求会超时**，故固定 16 点/请求并做断点续采 |
| 数据集选择说明 | 原计划用 `srtm30m`（NASA/USGS SRTMGL1 v003，`https://lpdaac.usgs.gov/products/srtmgl1v003/`），但采集期间该端点持续读超时（20 点请求亦超时）；改用同为 NASA 公开、约 30 m 全球覆盖的 ASTER GDEM。两者均为开放科学 DEM，不影响地形重建口径；采集脚本保留了快速切换数据集的能力 |

### 12.2 采集与重建方法（可复现）

1. `data/fetch_elevation.py` 按三个战区与 `GEO` 完全一致的经纬度包围盒，各采 **12×8 = 96 个 ASTER GDEM 实测控制点**（每点记录 lat / lon / elevation），共 288 个真实观测值。实测范围：孟良崮 93–834 m、塔山 0–417 m、徐蚌 5–112 m，与史料记载（孟良崮主峰约 536 m、白台山约 200 m、黄淮平原多在 50 m 以下）相符。
2. 公共接口对批量敏感且偶发超时：采用 **16 点/请求**、间隔约 1.1 秒、12 秒超时、最多 3 次重试；每批立即写入 `data/_raw_<area>.json` 断点文件，失败批次留待下一次运行补齐，因此脚本可重复执行。
3. 由控制点**双线性插值**加密到 **60×36 绘制网格**，再做一次 3×3 轻度平滑，用于等高线与高程晕渲的平滑绘制；等高线间隔按实测起伏自适应（孟良崮 100 m / 塔山 50 m / 徐蚌 10 m）。
4. 产物：`data/elevation.json`（完整控制点、绘制网格与元数据）、`data/elevation.js`（同源压缩副本）。
5. `data/embed_elevation.py` 把 `elevation.js` 幂等地内嵌进 `src/index.html` 的 `ELEVATION` 常量 —— 因为游戏需在 `file://` 下离线运行，不能用 `fetch` 读外部 JSON。

**诚实标注**：96 个控制点是**实测值**；60×36 绘制网格是**插值产物**（元数据 `render_grid.kind` 明确写 "NOT a full-resolution DEM"），不代表 30 m 原始分辨率。等高线由插值网格经 marching squares 生成（三战区分别 7 / 8 / 10 个层级），高程晕渲用 8 级色阶按实测范围归一化。

### 12.3 与历史地理的关系

- 高程属于自然地形骨架，在数十年尺度上基本稳定，因此现代开放 DEM 可用于重建 1947–1948 年的山地、丘陵、平原与水网格局（如孟良崮主峰约 536 m、白台山约 200 m、黄淮平原海拔多在 50 m 以下）。
- **1948 年的聚落、道路、铁路、水系走向与海岸线仍以军史史料和腾讯地图公开地名为准**（见 §10），不以现代 DEM 反推。
- 城镇建成区、水库、海岸人工改造可能造成局部高程差异；本图为教学示意，不作测绘图或工程依据。

### 12.4 地图合规

- 本作取得的是**开放高程数值数据**，不是地图瓦片、影像底图或在线地图服务；主游戏离线自绘 SVG，不加载任何第三方地图源，`src/index.html` 无外部脚本。
- 禁止清单（Google Maps / Apple Maps / Bing 海外版 / OpenStreetMap 境外瓦片 / Mapbox / Leaflet+OSM 等）一律未使用。
- 可选的真实底图对照页 `src/geography.html` 仍只使用**腾讯地图 GL JS**（白名单）默认代理模式，前端零密钥、GCJ-02、保留 WorkBuddy 代理占位符。
- 主图明确标注为教学示意格点图，非测绘图、非行政区划图；不标注军事禁区、涉密单位或未公开敏感坐标。

### 18.3 可访问性与工程约束

- 保留隐藏的原生 `<select id="comm">` 作为通信方式的唯一取值容器，自定义按键通过 `pickComm()` 写值并触发 `onchange`；保留表单语义与键盘可达性，所有 `onclick` 与 `id` 不变。

## 22. v1.4 地图交互现代化（2026-11-16）

### 22.1 无新增史实主张

本版是**输入方式与界面反馈层**：右键上下文命令、命令热键、悬停预览、小地图导航与信息泄漏修复全部由既有状态与既有命令引擎派生，不新增史实数据、坐标、电文或历史结论。史实与制图依据沿用 §9 / §12 / §19 / §20 / §21。

### 22.2 现代战略游戏交互惯例（D 类，非史实）

| 交互 | 现代游戏设计中的通行做法 | 本作实现 |
|---|---|---|
| 右键上下文命令 | 选中单位后右键目标直接下令，按目标类型（空地 / 敌 / 友）动态给出可用动作 | 右键空格＝机动 / 侦察 / 工事 / 待命；右键已侦知敌＝进攻 / 穿插 / 佯动 / 近迫 / 炮火；右键我方阵位＝选中 |
| Shift 修改命令属性 | 修饰键切换命令变体而不另开面板 | Shift+右键改用有线电话（更可靠但依赖线路） |
| 命令热键 | A 攻击、M 移动、S 停止、H 坚守、R 侦察等 | A / M / I / R / T / H / S；F 保留 Focus（定位选中），Esc 取消全部待令 |
| 目标预览 | 悬停显示作用范围与路径意图，再确认下达 | 目标框 + 我方单位出发的虚线意图箭头 + 已侦知敌标记；未侦知只显示地形指向 |
| 小地图 | 全图缩略 + 视口框 + 点击跳转 | 团 / 营 / 连级显示；我方点、已侦知敌点、视口框；师级全景自动隐藏 |
| Esc 层级取消 | 逐级或一次性退出当前待操作状态 | 一次清除师级待令、下级待令、阵位调整与右键菜单 |

以上均为**现代游戏设计约定**，不宣称还原 1947–1949 年的指挥所操作方式；历史命令语义、通信延迟与作业量仍取既有史实化参数。

### 22.3 信息不对称执行修正

核查中发现 `onCell()` 原先用 `S.enemies.find(e => e.x===x && e.y===y)` 直接比对**敌方真实坐标**，点击未侦知敌所在格会报出番号、装备与工事等级，绕开 v1.1 的迷雾。本版改为：

- 目标识别统一经 `foeAtCell()` → `foeSighted()` + `foeReportPos()`（最后确认位置）；
- 输出按 `foeLvl` 分级：确实＝番号 / 装备 / 工事，概略＝兵力区间，有迹象＝「当面之敌」，未侦知＝不出现；
- 右键菜单、悬停预览、小地图一律复用同一入口，**不另设事实源**。

这是 §19.4 边界的执行补强，不是新增史实主张。

### 22.4 合规

主游戏仍是单文件、离线自绘 SVG、零外部脚本 / 字体 / CDN / 瓦片；右键菜单为原生 DOM + 本地样式，不引入任何 UI 库。所有命令仍走 `issueOrder()` / `issueSubOrder()`，结算、评分、AI 与迷雾逻辑未改。
