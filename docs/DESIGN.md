## 1. 定位与边界

**一句话**：玩家是师长（1948-11 前该级称"旅"，见 §2），接到上级战斗命令后，在有限情报、有限参谋作业量和真实通信延迟下，把任务分解给团、营、连、班与直属分队，用符合当年作战原则的方式歼灭敌有生力量。

- 类型：**回合制、师级战术兵棋 + 指挥链模拟**，不是 RTS，也不是射击游戏。
- 基调：严肃的历史教学向推演。核心张力不是"操作手速"，而是**判断、集中兵力、选择打谁、何时不打、命令能不能按时传到**。
- 不做的事：不改写战役胜负与历史结论；不虚构真实历史人物言行；不由玩家扮演真实领导人；不渲染血腥；不做装备数值攀比。
- 架空范围：地图、番号、指战员姓名、具体战斗均为**师级局部示意**，剧本只借用宏观战役背景与作战原则。界面史实卡片标注 A 级来源。

## 2. 编制考据：为什么会有"旅"也有"师"

| 时期 | 上级 | 玩家这一级 | 下辖 | 依据 |
|---|---|---|---|---|
| 1946-06 — 1948-10 | 野战军 / 纵队 | **旅**（基本战术兵团，每旅 3 团） | 团 → 营 → 连 → 排 → 班 | 国防部《军队中的旅是怎样演变的》 |
| 1948-11-01 起 | 野战军 / 兵团 / 军 | **师**（旅统改称师） | 3 团（三三制） | 《关于统一全军组织及部队番号的规定》 |

设计处理：**界面统一称"师/师部"以便操作**，每张剧本卡标注"当时实际称谓：旅（1948-11 前）/ 师"，编制说明面板完整呈现沿革。师直属分队参考"军配直属炮兵团、工兵团及警卫分队"的编制精神，在师级缩比配置：炮兵营、侦察连、通信班、警卫连、担架队、辎重（支前）队。

**单位树（完整史实层级，UI 默认折叠到团）**

```
师部（师长、政委、参谋长、政治部主任）
├─ 第 1 团 ─ 1/2/3 营 ─ 各 1/2/3 连 ─ 各 1/2/3 班
├─ 第 2 团 ─ （同上）
├─ 第 3 团 ─ （同上）
└─ 师直属：炮兵营 / 侦察连 / 通信班 / 警卫连 / 担架队 / 支前队
```

- 地图上的**主棋子是团**；玩家可展开编制树，把**连或班"派遣"为临时小队棋子**（从母团抽调兵员），执行侦察、尖刀爆破、渗透、设伏、架线、喊话瓦解等任务。师长不直接微操 81 个班——这既符合指挥现实，又满足"指挥连、班与战士"的诉求。
- 每个班有班长（示意姓名）、战士数、党员/骨干比例，影响士气与任务成功率。

## 3. 核心循环（每回合 = 一个作战时段，约 2 小时）

```
① 受领：上级电报（任务、敌情通报、时限）
② 判断：情报等级、地形、敌我兵力比、昼夜与天气
③ 定下决心：选择主攻方向 / 预备队 / 阻援 / 是否不打
④ 下达命令：消耗"参谋作业量"，选择通信方式，产生传达延迟
⑤ 传达：命令进入队列，按延迟回合生效；可能中断、失真
⑥ 推演：分队移动 → 接触 → 战斗结算 → 敌方行动 → 随机事件
⑦ 战报：歼敌、伤亡、缴获、士气/弹药/疲劳变化
⑧ 补充与整训：支前运力补给、即俘即补、政治工作、休整
⑨ 上级评估：十大军事原则评分 → 进入下一时段 / 判定胜负
```

## 4. 核心机制：史实 → 玩法

| 史实 | 机制 |
|---|---|
| 十大原则第 4 条：集中 2–6 倍兵力、四面包围、力求全歼 | **局部兵力比**与**包围圈**加成；目标格四邻有我方单位即"合围"，敌不能撤退、歼灭率上升；分散平推则被判"消耗战"扣分 |
| 第 1、3、8 条：先打分散孤立弱敌、以歼敌有生力量为主、守备强固等待条件 | 敌单位有"孤立度 / 工事 / 装备"三属性；**先打弱敌**有显著加成；强攻坚固阵地须先近迫作业或炮火准备，否则伤亡剧增；占领格子本身不加分 |
| 第 5 条：不打无准备之仗 | 每回合**参谋作业量**有限（默认 4 点）；"侦察""近迫作业""炮火准备"是准备性命令，做了才有把握 |
| 第 7 条：运动中歼敌 | "穿插 / 迂回 / 追击"命令在敌移动或立足未稳时加成；敌固守工事后收益递减 |
| 第 9 条：以俘获补充自己 | 歼敌后可选**"即俘即补"**：按比例补兵员与弹药，但新补充的解放战士短期士气/训练偏低，需政治工作消化 |
| 第 10 条：间隙休整整训 | "休整"命令降疲劳、升士气，但给敌喘息时间（敌可能构筑工事或增援） |
| 电台 / 有线电话 / 司号 / 通信员 / 小喇叭 | **五种通信方式**决定命令延迟、可靠性与适用层级；越往下传达越慢（师→团 +0、→营 +1、→连 +1、→班 +2）；线路被炸断、敌机干扰会造成命令中断 |
| "东总命令十分钟传到连" | 简短命令（停止、待命、转移）用**司号+暗语**可近实时下达，但只能表达简单意图 |
| 近迫作业 / 交通壕、飞雷炮 | "近迫作业"逐回合累积**工事推进值**，把冲击距离压到数十米，大幅削弱敌远战火力；是攻克"硬核桃"的唯一低伤亡解 |
| 夜战近战 | 夜间敌火力（尤其美械）削弱，我方"夜袭"加成；但疲劳与误伤风险上升 |
| 543 万民工、小车 88 万辆 | **支前运力**是全局资源：决定每回合弹药粮食补充、伤员后送（降疲劳）、工事材料；民工队可被空袭，且远离补给线时效率下降 |
| 立功运动 / 三大互助 / 诉苦三查 | "政治工作"行动：士气恢复、降低溃退概率、加速解放战士转化；对应"支部建在连上"的基层韧性（连排干部伤亡后仍可自动代理，避免整建制崩塌） |
| 整编师旅两团制、重火力集中但协同差、派系保存实力 | 敌单位**火力强、协同弱**：敌增援有"迟疑"概率，被分割后互相支援效率低；美械/日械/国械决定火力与弹药消耗 |
| 战役代价（淮海伤 13.6 万、牺牲 3.1 万余） | 结算显示"代价"评分；以优势兵力打消耗战、反复强攻会拉低评价 |

## 5. 数值框架（原型实现口径）

**单位属性**：`men`（兵员）、`morale` 0–100、`fatigue` 0–100、`ammo` 0–100、`training`（训练/装备系数）、`entrench` 0–3（工事）、`pos`、`order`。

**有效战力**

```
E = men × training × (0.45 + morale/180) × (1 − fatigue/260)
    × ammoFactor × terrain × tactic × night × encircle × intel × rng(0.85~1.15)
```

- `ammoFactor = 0.35 + 0.65 × ammo/100`（弹尽仍有白刃/近战能力，对应近战传统）
- `terrain`：高地 1.25 / 村落 1.20 / 树林 1.10 / 平原 1.00 / 河流 0.70（进攻）/ 公路（机动 +1）
- `tactic`：进攻 1.00、穿插 1.15（对运动/孤立之敌）、夜袭 1.20（夜间）、近迫作业后突击 1.35、佯动 0.55（但吸引敌火力）、防御 1.10、仓促进攻 0.75
- `night`：夜间我方 ×1.10、敌美械火力 ×0.75
- `encircle`：局部兵力比 ≥2 → ×1.15；≥3 → ×1.30；四邻合围 → ×1.25 且敌不可撤退
- `intel`：敌情"不明" ×0.80、"概略" ×0.95、"确实" ×1.05
- `entrench`：每级为防守方减伤 12%；近迫作业推进值可抵消

**战斗结算**：接触（切比雪夫距离 ≤1）时先聚合我方参战单位求 `ΣE`，再按局部兵力比、合围、近迫推进、敌工事与炮火压制修正，双方同时结算：

```
dmgE = ΣE × 0.110 × ratioBonus × encircleBonus × trenchBonus × (1 − 0.12×敌工事)
dmgU = E_e  × 0.075 × (1 − 0.10×我方平均工事) × (合围 ? 0.85 : 1)
```

两式各乘 `0.9~1.1` 随机因子（带种子 PRNG，可复现）。**上述系数是原型平衡参数，不是史实数据**。合围时敌不可撤退，并按"歼灭/俘获"比例转化，产生俘虏与缴获；`men≤0` 或士气 ≤15 判为成建制损失。

**近迫作业**：每执行一次，执行单位 `trench` 等级 +1（上限 3，`trenchBonus = 1 + 0.16×等级`），同时把目标格守敌工事削 1 级——对应"壕沟挖到敌前沿、敌轻重武器失去效用"。**夺取据点**：攻坚剧本中歼灭据点守敌后，就近部队进入该格，夺取状态保持（除非敌重新占据），避免"歼敌却未占地"的判定失真。

**每回合资源**：参谋作业量 4 点（每道命令 1 点，越级指挥到班 +1 点）；支前运力按剧本给定，每回合分配。

**通信表**

| 方式 | 基础延迟 | 可靠性 | 限制 |
|---|---|---|---|
| 有线电话 | 0 回合 | 0.95 | 目标不能机动；线路可能被炸断 |
| 电台（暗语） | 1 回合 | 0.90 | 可越级；长命令须 2 回合；有暴露风险 |
| 司号 | 1 回合 | 0.88 | 仅简短命令（停止/待命/转移/冲锋） |
| 通信员 | 2 回合 | 0.72 | 不受电子干扰；可被俘/延误 |
| 小喇叭 | 0 回合 | 0.92 | 仅同格连以下分队 |

**士气/疲劳**：伤亡 −、被合围 −、连续作战 −；歼敌 +、支前到位 +、政治工作 +、休整 +；`morale < 25` 有溃退判定，但班级"骨干代理"使单位不会瞬间整建制消失。

## 6. 上级评估：十大军事原则评分卡

结算时按 8 项给"上级评语"，而非单一分数：

1. 是否以歼敌有生力量为主要目标（而非抢地盘）
2. 是否先打分散孤立之敌
3. 主要战斗是否形成 ≥2 倍局部优势
4. 是否四面包围、力求全歼、不使漏网
5. 是否避免得不偿失的消耗战（伤亡比）
6. 是否有准备（侦察 / 近迫 / 炮火准备）
7. 是否在运动中歼敌、并相机转换阵地攻击
8. 是否利用间隙休整、及时补充与即俘即补

## 9. 技术实现

- **单文件** `src/index.html`，零外部依赖，双击即可离线运行；UTF-8，无网络请求、无 localStorage 依赖（可选存档）。
- 代码分层：`DATA`（剧本/地形/编制/史料）→ `STATE`（唯一状态对象）→ `ENGINE`（命令队列、移动、战斗、事件、结算）→ `RENDER`（地图、树、面板、日志）→ `UI`（事件绑定）。
- 随机数使用**带种子的 PRNG**，同一剧本可复现，便于调试与复盘。
- 状态与视图分离：任何数值变化都经 `commit()` 触发重绘；战斗日志是状态的函数，不做隐式副作用。
- 验收：三个剧本均可完整走完并给出胜负与评估；无 JS 报错；命令延迟与包围/集中加成可在日志中复核；全部史实文案可在 `SOURCES.md` 找到对应条目。

### 11.3 开放式指挥模型（史实依据）

- **"我们不遥制"**：1947-05-12 中央军委电"究打何路最好，由你们当机决策，立付施行，我们不遥制"。
- **"机断专行，不要事事请示……但将战况及意见每日或每两日或每三日报告一次"**：中央军委对战役前委的授权。
- 因此上级命令 = **方针（真实电文）＋ 战役意图 ＋ 约束 ＋ 时限**，**不指定主攻点、不指定攻击路线、不指定必须占领的格子**。唯一硬性约束来自史实（如塔山电令"绝对不能采取运动防御"）。
- 玩家可自由：先打哪一路、是否分兵、是否忍耐待机（`wait`）、是否围而不打（`envelop`）、是否主动放弃某些地方（`abandon`）、是否开展政治攻势（`persuade`）、如何分配牵制与突击、何时休整、何时上报、何时收兵。
- 新增 `reportSituation()`（每 2–3 时段上报，影响"上级信任"）与 `finish('report')`（玩家自主收兵）。
- **开放式评估**：不再判定"是否占领某格"，而是统计九维战略分 —— 歼敌量、伤亡比、局部优势、合围、准备程度、**实际控制的真实交通线节点数**、决心多样性、按期上报、代价；并保留 8 项"十大军事原则评分卡"。终局给出 5 类结局（大捷 / 达成意图 / 未竟全功 / 消耗战 / 部队失去战斗力）与"本级决心记录"复盘。
- 交通线控制取代固定目标，对应"直出宿县，截断宿蚌路""控制整个北宁线"的史实逻辑；主动放弃地点不扣分，对应《集中优势兵力》第 9 段"可以允许放弃某些地方"。

### 11.4 真实地理格点图

## 12. v0.3：2.5D 等距立体地图（已被 v0.4 取代，保留作设计沿革）

### 12.1 目标与原则

用户提出「地图能不能设计成 2.5D」。回答是肯定的，且**只改渲染层**：真实经纬度投影（`proj`）、18×11 格网、地名 / 水系 / 铁路 / 公路数据、单位坐标、战斗与推演逻辑全部不变，因此史实准确性与既有测试结论不受影响。

### 12.2 投影与地块

- 等距变换：`cx = (x − y) × tw/2 + ox`，`cy = (x + y) × th/2 + oy`；`tw=50, th=25`（2:1 经典等距），`ox=280, oy=58`，画布 `800×480`。x 增大向右下、y 增大向左下。
- 每格绘 3 个多边形：菱形顶面、左侧面、右侧面；侧面厚度 `depth=16`。顶面按地形明度 ×1.24，左侧面 ×0.70，右侧面 ×0.46，形成统一左上光源的立体感。
- **地形高度分档**（`ELEV`）：山地 / 崮 +22、丘陵高地 +14、敌据点 +12、村镇 +8、树林 +6、平原 / 公路 / 铁路 0、河流 −6、海域 −10。相邻格高度不同形成台阶，直观呈现沂蒙山区、塔山白台山、徐蚌水网。
- 绘制顺序按 `x + y` 升序（同层按 x 升序），保证前排地块正确遮挡后排侧面。

### 12.3 史实要素与图元的立体适配

- 河流 / 公路 / 铁路折线改用 `isoLine()`：先 `proj` 到格，再 `iso` 到菱形中心，并按该格高度把 y 上移，线随地形起伏。线宽改为像素级（河流 5、铁路底 6 + 金色虚线 2.4、公路 2.6）。
- 真实地名改为浮动标签（深色框 + 金色字）+ 细引线；同格只显示一个，并用 `usedLabels` 做垂直避让（冲突时上移 17px，最多 6 次），避免与后排标签和棋子重叠。
- 单位改成立体棋子：底部椭圆投影阴影 + 柱身 + 顶盖（我军）或菱形旗（敌军）；同格多个单位左右错开，超过 2 个显示 `+N`。仍按 `x+y` 排序绘制。
- 选中 / 目标高亮改为菱形描边；炮火准备标记跟随顶面高度。

### 12.4 交互与合规

- 点击热区从「透明 HTML 网格」改为**菱形 SVG 地块本身**：每个 `<g class="tile" data-x data-y>` 内含 `<title>`（悬停提示），事件委托用 `closest('[data-x]')` + `getAttribute`。其余图元 `pointer-events="none"`，点击可穿透到地块，热区与菱形精确贴合。
- CSS 容器 `aspect-ratio: 800/480`，`preserveAspectRatio="xMidYMid meet"`；无任何外部依赖，主游戏仍可离线运行。
- 2.5D 只是视觉表现，**不改变**地理数据与地图合规口径：仍是自绘教学示意格点图，非测绘图 / 行政区划图；真实底图对照仍由 `src/geography.html`（腾讯地图白名单）承担。

### 12.5 验收

`node tests/smoke_test.js` 全部通过；新增断言覆盖：198 个菱形地块、`viewBox 800×480`、每格 3 个多边形（实测 595）、单位投影阴影（实测 17 个椭圆）、真实地名 / 河流 / 津浦与陇海两条铁路叠加、等距投影方向、地形高度分档、侧面明暗色合法性。另做边界检查：三个剧本的 SVG 均无 `NaN/undefined/Infinity`，所有坐标落在画布内。**用户反馈 2.5D 效果不好，v0.4 已移除该渲染层。**

## 14. v0.5：多级比例尺战术地图与营连级指挥

本版回答一个问题：**如何让地图同时"信息丰富"和"容易理解"，并让放大到团、营、连层级具有真实的指挥意义**。

### 14.1 问题定义：矛盾不在信息量，而在同屏密度

把公路、水系、铁路、城镇、村落、地形、湖泊、等高线、单位标号全部画在一张 18×11 全景图上，结果是地名互相压盖、线条交织、决策信息被噪声淹没。真实军用地图从不这样做，它依靠**比例尺分级综合（cartographic generalization）**：小比例尺只保留骨架，放大后逐级展开细节。因此正确解法不是削减数据，而是让**信息的呈现密度随比例尺变化**，并保持大致恒定的屏幕密度。

三条设计原则：

1. **一套坐标**：所有要素共用经纬度投影得到的世界坐标；缩放只改变视口，不产生第二套地图数据，从根本上避免层级间坐标错乱。
2. **符号尺度解耦**：线宽、字号、图标半径乘 `u = 1/k`。放大 9 倍时世界坐标里的尺寸缩小 9 倍，屏幕上的尺寸不变 —— 线不会变粗、字不会变巨大。
3. **信息按需出现**：细节层（战术要点、子格、子格卡片）只在放大后进入 DOM；密集处的次要地名标签自动避让或省略，悬停 / 点击才给出完整注记。

### 14.2 三级比例尺与视口模型

| 级别 | viewBox | 显示地幅 | 指挥对象 | 展开的要素 |
|---|---|---|---|---|
| Z1 师级全景 `k=1` | `0 0 800 480` | 全战区 18×11 格 | 师部 → 团 / 师直属 | 枢纽与县城级居民地、干线公路、干流 / 运河、铁路、抽稀等高线、山系骨架 |
| Z2 团级战术 `k=3` | 约 `266.7×160` | 约 6×4 格 | 团 → 营 / 派出连 | 追加 3 级村落、支线公路与乡村道、支流与季节河沟、湖泊 / 海域 / 滩涂、全部等高线、史料要点符号 |
| Z3 营连部署 `k=9` | 约 `88.9×53.3` | 约 2×1.5 格 | 营 → 连 → 班 | 追加 3×3 子格编号、**每个子格的高程 / 要点 / 攻防效应卡片**、局部加密等高线 |

世界坐标恒为 `0..800 × 0..480`，`CW=800/18`、`CH=480/11`。视口由 `S.view={z,cx,cy}` 描述：

```
w = 800/k, h = 480/k
x = clamp(cx - w/2, 0, 800-w),  y = clamp(cy - h/2, 0, 480-h)
viewBox = [x, y, w, h]
```

- **连续投影**：`geoXY()` 直接把真实经纬度线性映射到世界像素，不再先 `round` 到整数格。折线因此是平滑连续的真实走向，放大后不会退化为阶梯折线；整数格判定仍沿用 `proj()`，保证与地形、地名列表一致。
- **交互**：滚轮以鼠标位置为中心缩放（`screenToWorld`）、`＋/－` 与三级按钮切换、按住拖拽平移（拖拽中只改 `viewBox` 属性，松手才重建热区，避免逐帧全量重绘）、「复位全景」「定位选中单位」。放大时若未指定中心，自动聚焦所选单位或最近的敌军，避免落到无信息的空白地幅。
- **热区**：Z1 为 198 个师级格；Z2 / Z3 只生成可见范围内的 `格 × 3×3` 子格（实测 315 / 54 个），带 `data-x/y/sx/sy`，DOM 规模与信息密度同步受控。

### 14.3 制图分级与符号系统

信息丰富而可辨，靠的是**等级符号**而不是更多颜色。全图只用四组语义色：地形低饱和绿棕（背景）、水蓝、交通金棕 / 红棕、居民地暖白，部队绿 / 红。

| 要素 | 分级 | 符号 |
|---|---|---|
| 居民地 | 1 枢纽 / 主战场，2 县城 / 要点 / 车站，3 村落 / 阵地，4 图外注记 | 实心方块（粗字）→ 空心圆（中字）→ 小方（小字）；Z1 只显示 1–2 级 |
| 公路 | 1 干线、2 支线、3 乡村 / 山间道 | 实线 → 长虚线 → 点线；Z1 省略 3 级 |
| 水系 | 1 干流 / 运河、2 支流、3 季节河沟 | 按等级递减线宽，3 级加虚线；Z2 起标注河名 |
| 铁路 | 单一等级 | 深色路基 + 金色主线 + **等距短横枕木**，车站用方框符号 |
| 面状水域 | 海域 / 潮间带 / 河漫滩 | 闭合 `path` 填充 + 岸线，Z2 起标注名称 |
| 等高线 | 主曲线 / 首曲线 | 主曲线加粗并标注高程；Z1 抽稀，Z2/Z3 全画并局部加密 |
| 战术要点 | 10 类 | 制高点三角、桥梁双横、渡口波线、工事雉堞、隘口箭头、树林圆冠等语义图标 |
| 部队 | 团 / 分队 / 敌军 / 已部署下级 | 圆形、菱形旗、方框任务环；Z3 团级标号缩到格角，避免压住子格中心 |

**标签避让**：地名按等级排序，逐个尝试上移并做矩形碰撞检测，冲突则继续上移，四次仍冲突才落位；同格按半格精度去重；Z2/Z3 先按视口过滤，视口外的地名不参与避让计算。

**图层控制**：12 个图层（地形晕渲、等高线、湖海滩涂、河流水系、铁路、公路、城镇村落、地名注记、坐标格网、战术要点、战术子格、部队标号）可独立开关，默认按 LOD 自动分级，「自动分级」一键复位。

### 14.4 易理解性的具体措施

1. **面包屑与比例尺条**：工具栏常显「当前级别 · 显示地幅 · 每格约 km / 每子格约 km · 本级可指挥层级」；地图下方给出随缩放变化的线段比例尺、指北针与图幅宽度。
2. **渐进披露**：默认只画标签；地名、地形、要点、史料注记、敌我兵力的完整信息放在悬停提示与点击后的「地形情报卡」，不堆在图上。
3. **分组图例**：按地形 / 水系 / 交通 / 居民地 / 部队与部署五组，每组用真实 SVG 符号小样（铁路枕木、公路线型、等级居民地符号），而不是纯色块。
4. **子格四行卡片**（Z3）：`方位 · 高程` / 要点符号 / `要点类型` / `防+X% 攻+Y%`，行距大于字号，且只绘制完整落在视口内的子格，不出现半截文字。
5. **一致的点击语义**：任何级别点击都走 `onCell(x,y)`，命令下达与单位选中流程不被缩放打断；处于部署模式时才改为「点子格即部署」。放大视图里仍可指定师级格目标。
6. **显式 / 派生分层**：史料要点用大符号 + 名称，真实高程 / 交通线派生的普通要点用小符号；密度高但视觉层级分明。

### 14.5 放大后的局部地形细化（不伪造数据）

若沿用全战区 60×36 晕渲色块，Z3 视口内只剩约 6×4 个矩形，会被拉伸成一整片纯色；全战区 100 m 间隔的等高线在 2 格地幅里也可能一条都没有。本版做两件**只作用于显示层**的处理：

- `localHypsometric()`：在可见范围内按 `elevAtGrid()` 对**同一插值网格**重采样（Z2 步长 3.0、Z3 1.6 世界单位），并用**视口局部高程范围**拉伸色阶（下限 10 m 动态范围），恢复局部层次。明确标注：不新增实测点、只是重采样与局部归一化。
- `localContourLevels()` / `renderLocalContours()`：按视口真实高程范围派生层级，间隔细化为 `原间隔 / 2`（Z2）或 `/ 5`（Z3，最小 5 m），线段裁剪到视口。数据仍来自同一 ASTER GDEM 插值场。

### 14.6 营连级子格部署：放大不是"看得更清楚"，而是"指挥得上"

这是本版把地图与玩法接成闭环的关键。原先团下辖 3 营 × 3 连 × 3 班虽在编制树中完整存在，但所有派出的连、班都挤在同一个师级格中心，放大地图不会带来任何新的指挥能力。

**战术子格**：每个师级格细分为 `3×3 = 9` 个子格，世界坐标 `(x+(sx+0.5)/3, y+(sy+0.5)/3)`。每个子格必有一个要点：

- **显式史料要点**：三个战区共 24 个（孟良崮主峰、大庵顶、垛庄退路、界牌通道、塔山铁路桥头、白台山制高点、打渔山滩涂、碾庄圩水壕、符离集铁路桥、运河车站渡口……），逐条附史料依据；`featureCells()` 做冲突消解，把落在同一子格的要点按曼哈顿距离分配到最近的空子格，保证「图标位置 = 可点中的子格」。
- **派生要点**：其余子格由**真实高程相对高差 + 该格真实地形 / 水系 / 交通线**派生（制高点、低洼、渡口、桥梁、通道、树林、村落、开阔地等），并写明派生依据与相对高差，不虚构地名。

**部署与任务**：展开编制树选中营 / 连 / 班 → 「战术部署到要点」→ 在团级 / 营连级视图点子格；同时从 5 类任务中选择：固守要点、突击队、侧翼迂回、火力掩护、渗透侦察。要点基础效应与任务系数相乘，得到该部署的 `def / att / obs / mv`。约束：只能部署到本团所在格及相邻格、同一子格不可重复占用、**每团每时段最多调整 3 处**，因此必须取舍 —— 与「集中优势兵力于一点」的作战方针同源。渗透侦察任务会提升敌情等级。

**战斗结算接口**（唯一改动点，不动既有引擎结构）：

```
dmgE = ... × tacticalFactor(allies,'att').f
dmgU = ... / tacticalFactor(allies,'def').f
```

`tacticalFactor()` 严格按 `regId / subId / from` 归属母团，不把友邻团的部署计入；总量钳制在 `0.88 ~ 1.32`，保证开放式评估的既有分档不被破坏。战报中写明「N 处营连要点部署生效」。因此放大视图具有实际指挥价值：占据制高点组织防御、把突击队放在便于展开的开阔地、让侦察分队进树林渗透，都会改变战斗结果。

### 14.7 数据来源与诚实标注

- 战术要点位置依据史料方位或真实地名坐标，精确边界为符号化示意；`approx=true` 的条目在情报卡中显式标注。
- 面状水域只画史料 / 地理明确的（锦州湾、打渔山潮间滩涂、淮河河漫滩）。微山湖、洪泽湖在图幅之外，只作**图外注记**，不伪造岸线；孟良崮图幅明确标注「无大型天然湖泊」。
- 局部晕渲与加密等高线是**同一插值网格的重采样与局部归一化**，元数据与界面均声明「无新增实测点」。
- 1948 年聚落、道路、铁路、水系走向仍以军史史料与腾讯地图公开地名为准，不由现代 DEM 反推。

## 15. v0.6：团以下单位的解聚、指挥链与作战方式

用户指出 v0.5 的实质缺陷：放大到团级 / 营连级后，地图上除 3 个团与师直属分队外**没有可指挥的下级单位**；编制树里的 3 营 × 3 连 × 3 班只是静态节点，没有兵力账目、位置、命令与独立行动能力，v0.5 的"部署"也只是加成记录。本版按兵棋的**聚合—解聚**（aggregation / disaggregation）模型重建。

### 15.1 为什么是解聚，而不是"再加几个棋子"

师级兵棋不能把 81 个班同时画在 18×11 全景图上（信息过载），也不能凭空生成不属于任何团的独立单位（编制失真）。正确做法是：**同一支部队在不同比例尺下以不同聚合度呈现**——师级看团，团级看营，营连级看连 / 班；各级显示的是同一批人，只是粒度不同。因此：

- **单一事实源**：营 / 连 / 班实体就是编制树里的节点本身（`findSub().node === S.subs[id]`），不是另一份拷贝。
- **兵力账目严格守恒**：`团.men = Σ营.men = Σ连.men = Σ班.men`。初始化用整除 + 余数分配 `splitMen()`；伤亡用最大余数法 `apportion()` 逐级分摊；补充 `applyReplenish()` 逐级回补；派出独立分队沿"班 → 连 → 营 → 团"链逐级扣减。任何时刻 `subBookOK(reg)` 均为真（测试逐项验证）。
- **不重复计算火力**：下级实体代表任务编组与指挥关系，兵力账目在师级聚合层结算；下级通过任务编成、要点控制、战术动作修正聚合结果。这既避免"团 2900 人 + 三个营各 967 人 = 5800 人"的重复计数，又让下级指挥真实影响战果。界面明确标注"编成占母团 33%"。

### 15.2 三级尺度与真实编制尺度相称

| 视图 | 单位 | 地幅 | 对应真实量级 |
|---|---|---|---|
| 师级全景 | 团（1 格） | 约 5–11 km | 团进攻 / 防御正面 |
| 团级战术 | 营（1 子格 = 1/3 格） | 约 1.7–3.7 km | 营防御正面约 1–2 km |
| 营连部署 | 连 / 班（1 微格 = 1/9 格） | 约 0.5–1.2 km | 连正面约 500–800 m、班约 100–200 m |

`initSubPlacement()` 按前三角阵位铺开：每团 3 营按主攻 / 助攻 / 预备队占三个子格，每营 3 连占子格内三个微格，每连 3 班在微格内小偏移。**一进入团级视图就能看到 9 个营**，不需要玩家先"部署"才有单位 —— 直接解决"没有可供指挥的单位"。团机动时 `syncSubPositions()` 按团位移平移所属全部阵位，玩家手动调整的相对偏移得以保留。

### 15.3 指挥链：层级越深，代价越大

史实依据：电台暗语与司号按师—团—营—连逐级下传，"停止待命"顺利时不到十分钟到连；有线电话在运动战中自下而上架设；线路炸断后靠通信员徒步（§9、§6）。因此：

| 层级 | 参谋作业量 | 传达延迟增量 | 命令集 |
|---|---|---|---|
| 团 / 师直属 | 1 点 | 基线 | 19 类师级命令 |
| 营 | 1 点 | +1 时段 | 6 类任务编成 |
| 连 | 2 点 | +2 时段 | 13 类战术动作 |
| 班 | 2 点 | +2 时段 | 5 类专门小组 |

`issueSubOrder()` → `S.subOrders` 队列 → `deliverSubOrders()` 按 `COMM[comm].delay + SUB_LEVEL.delay` 生效，并按通信可靠性掷点判定传达中断（有线电话受 `lineBonus` 加成）。司号只能传达简短命令。传达队列与师级命令合并显示，标注层级与生效时段。

### 15.4 营：任务编成决定"集中优势兵力于一点"

依据《集中优势兵力，各个歼灭敌人》"以少数兵力牵制敌军的其余各旅（或团）"与塔山电令"各级掌握三分之一至三分之二预备队"。6 类任务带 `commit`（兵力投入系数）与攻防修正：

| 任务 | 投入 | 作用 |
|---|---|---|
| 主攻 | 1.00 | 主要突击，攻击修正最高 |
| 助攻 | 0.75 | 另一方向施压 |
| 牵制 | 0.35 | 降低敌增援 / 突围漏网概率 |
| 预备队 | 0.00 | 不投入正面，吸收伤亡、降低我伤亡 |
| 固守要点 | 0.60 | 防御修正最高 |
| 阻援 / 设伏 | 0.50 | 围点打援、切断退路 |

默认编成为 `主攻 / 助攻 / 预备队`。结算时计算**主攻集中度** = 主攻营投入兵力 / 全部投入兵力：两个以上营主攻且集中度 ≥ 0.55 → 攻击 ×1.12（集中优势）；无主攻、兵力平分 → ×0.94（对应"反对平分兵力对付诸路之敌"）。牵制与阻援营使漏网判定概率按 `subPinFactor()` 下降。战报写明"集中 2 个营主攻；以一部牵制敌其余各部"。

### 15.5 连与班：战术动作产生具体效果

连是基本战术单位，13 类动作分 4 组（进攻 / 火力与工事 / 侦察与政治 / 保障），在 `subPhase()` 于下一时段生效：

- 近迫作业 → 营交通壕等级 +1（削敌工事、缩短冲击距离，对应锦州 / 碾庄 / 双堆集战法）
- 尖刀爆破 → 当面敌工事 −1；火力掩护 → 下时段该营攻击增强
- 构筑工事 → 营工事 +1；侦察 → 师部敌情等级 +1
- 喊话瓦解 → 当面敌士气 −5（《敦促杜聿明等投降书》）；政治工作 → 士气回升
- 架线 → 有线命令可靠性提升；休整 → 疲劳 / 弹药 / 士气恢复
- 突击 / 夜袭（限夜间）/ 设伏 → 该营本时段攻击修正

班可编为侦察组 / 爆破组 / 火力组 / 架线组 / 喊话组，也可"派出"为师部直接指挥的独立棋子（沿账目链抽兵，守恒）。展开某个连后，其 3 个班在微格内以三角符号显示。

### 15.6 结算接口与战报

`subTacticalMod(allies)` 汇总三类输入：营任务编成（集中度 / 牵制 / 预备队 / 固守）、每个营所在子格的真实要点效应（史料要点或高程 / 交通线派生）、连战术动作累积状态。攻防系数钳制在 `0.85 ~ 1.45`，在 `resolveCombat()` 中：

```
dmgE = ... × mod.att      dmgU = ... / mod.def
applyLoss(u, 伤亡)        // 逐级分摊到营 / 连 / 班
```

一次性动作标志在结算末尾由 `clearSubActionFlags()` 清除，避免重复生效。战报写入编成说明与要点生效数，玩家能直接看到"我把两个营设为主攻"带来的差别。

### 15.7 指挥界面（信息丰富且容易理解）

- **编制树**：营 / 连 / 班节点显示任务、兵力、在编状态，点选即成为指挥对象，并自动展开到该级、放大到可见层级。
- **单位详情**：层级、隶属、兵力 / 兵员上限、士气、弹药、疲劳、编成占母团比例、当前任务、阵位（格 / 子格 / 微格）、要点效应、调整阵位 / 地图定位 / 派出按钮。
- **命令面板**：按选中层级自动切换，不会把 19 类师级命令、6 类营任务、13 类连动作混在一起；连动作按用途分组。
- **地图**：营 = 任务色方框、连 = 圆、班 = 三角，选中加外环；点地图上的单位即选中并指定为指挥焦点；有单位驻守的子格用深色底衬、只保留一行方位高程，避免与单位符号争空间。
- **工具栏 / 图例 / 情报卡**：显示指挥焦点、本级可指挥层级；图例新增下级单位符号组；情报卡可"指挥此单位"。

## 16. v0.7：敌我双方标号牌与态势可读性

用户反馈：团级 / 营级 / 连级的敌我单位显示太小、不易看清。核查后发现问题不止"尺寸"一项，而是五个叠加的缺陷。

### 16.1 诊断

1. **符号尺寸不足**：v0.6 用 `a = 小系数 × u` 画圆 / 方 / 三角，屏幕直径仅约 12–20px，番号只有一个字，兵力与任务挤在牌外的小字里。
2. **敌我态势不对称**：我方已解聚为 9 营 / 27 连 / 81 班，敌方仍是 4 个孤立菱形"敌"——放大后"我方密密麻麻、敌方空空荡荡"。
3. **同名单位歧义**：三个团各有"1营 / 2营 / 3营"，地图上同时出现多个"1营"，无法判断归属。
4. **视口裁切**：9 倍视口仅约 2 格宽，边缘单位被裁成半截牌；若强行钳制到边缘，多个牌又挤成一团。
5. **注记压字**：地名标签与单位牌互相压盖；敌我初始相距数格，局部视图里常常只看到一方，缺少方位感。

### 16.2 统一标号牌（unit badge）

放弃"圆 / 方 / 三角"的小符号，改为**带深色底板的两行标号牌**，敌我共用一套版式、靠形状与颜色区分：

| 维度 | 我方 | 敌方 |
|---|---|---|
| 形状 | 圆角矩形 | 四角斜切的八边形 |
| 边框 / 底色 | `#89e6c0` / `#0c241b` | `#f0937f` / `#2a1512` |
| 左侧竖条 | 该营任务色（主攻 / 牵制 / 预备队…） | 敌方红 |
| 右上角角标 | 所属团序号（1/2/3，团色） | 敌单位序号 |
| 内容 | 番号 + 兵力 / 任务 | 番号 + 兵力 |

## 17. v0.8：移动设备友好（手机 / 平板）

### 17.1 核心判断

移动端适配不是"把桌面页面等比缩小"，而是要重构信息架构。桌面版的前提是 **1200px 以上宽度 + 鼠标精确指针 + 三栏同时可见**；手机的前提是 **390px 宽、单手操作、无 hover、无滚轮**。若只是把三栏堆叠成一条长页面，玩家要在地图、编制树、命令面板、结束时段按钮之间反复上下滚动，指挥链会断裂。因此本版把"同时可见"改为"单焦点任务流 + 按需展开"，同时**完整保留桌面端三栏行为**。

### 17.2 三档响应式布局

| 视口 | 布局 | 说明 |
|---|---|---|
| >1180px（桌面） | 三栏 `274px / 自适应 / 318px` | **完全不变**，全部既有交互与测试保持 |
| 901–1180px（平板横屏 / 小桌面） | 两栏 | 地图 + 命令面板并排；编制树移到下方全宽可滚动区；日志置底 |
| ≤900px（手机竖屏 / 平板竖屏） | 单栏 + 底部操作栏 + 抽屉 | 精简状态条、地图、情报卡常显；编制 / 命令 / 指示 / 更多通过底部按钮打开 bottom sheet |
| ≤420px（小屏手机） | 紧凑变体 | 字号、内边距、命令网格进一步压缩；命令按钮两列 |

抽屉用 **CSS 类切换**实现：DOM 节点不移动、ID 不变，`renderAll()` 照常按 ID 更新，`body[data-sheet]` 控制遮罩，`.msheet-open` 把对应面板变成底部滑出层（`max-height:min(78vh,680px)`、圆角、把手条）。这样既避免重复 DOM 导致的状态不同步，也保留了所有 inline 交互。点遮罩、再点同一 tab 或按 `closeSheet()` 均可关闭。

**状态条**：把顶栏六个按钮 + 六枚 chip 压成一行可换行的精简信息（剧本、时段、昼夜、敌情、作业量、当前比例尺），顶栏全部功能收进「更多」抽屉。

**底部操作栏**：主按钮「▶ 结束时段」独占满宽首行（最常用、最需要大目标），第二行四个等宽 tab。遵循拇指可达区与 WCAG 触控目标 ≥44px。

**全屏地图**：手机上地图约 240px 高，细节不足。提供「全屏」浮动按钮进入全屏：`flex` 布局让地图撑满工具栏以下全部空间，隐藏情报卡 / 图例 / 地理说明，图层开关仍可用，右下角固定 `＋ / － / 退出` 三个按钮。

### 17.3 地图比例自适应（避免变形）

原 `.map` 强制 `aspect-ratio:800/480` + `min-height:380px`，在 390px 宽手机上比例被破坏，而 SVG 用 `preserveAspectRatio="none"` 会把地形纵向拉伸。本版：

- 普通移动端恢复 `aspect-ratio:800/480`、`height:auto`、`min-height:240px`，师级全景**完整显示整个战区**；
- `visibleBox()` 增加容器比例检测：当容器宽高比与 800:480 偏离超过 0.06（例如全屏竖屏）时，在**保持视口面积不变**的前提下按容器比例重算 viewBox 宽高：
  ```
  area = (800/k) × (480/k)
  h = √(area / aspect_ratio_container),  w = area / h
  ```
  这样缩放级别语义不变、不变形、不凭空增加信息；桌面比例下结果与旧版完全一致（测试断言 `0 0 800 480` 仍通过）。

### 17.4 触控手势（Pointer Events 统一）

把原来 `onmousedown/onmousemove/onmouseup` 改为 `onpointerdown/move/up/cancel`，一次覆盖鼠标、触摸与触控笔；`touch-action:none` 阻止浏览器在地图区域抢走滚动 / 缩放手势。

| 手势 | 行为 |
|---|---|
| 单指 / 鼠标拖拽 | 平移；拖拽中只改 `viewBox` 属性，松手才重建热区，避免逐帧全量重绘 |
| 双指捏合 | 记录双指间距，松手时按 `末距/初距 > 1.25` 放大一级、`< 0.8` 缩小一级，以双指中点为缩放中心 |
| 双击（仅移动端） | 放大一级；桌面双击行为保持不变，不会误触发 |
| 滚轮 | 保留，以鼠标位置为中心缩放 |
| 点击 | 移动端按 `pickCellAt()` **直接把屏幕坐标换算成世界坐标再落格 / 子格 / 微格**，不依赖细小热区命中，解决 18×11 格在小屏上每格仅约 20px 的误触问题 |

捏合 / 双击后设置 `_suppressClick`，避免手势结束的 click 被误判为选格命令。

### 17.5 替代 hover-only 信息

`<title>` 悬停提示在触屏上不存在。本版把格 / 子格 / 微格的地形、实测高程、要点、攻防效应、驻守单位与史实依据全部收进**常显的情报卡**（`renderMapInfo()`），点击即更新；图例、电文、战报通过抽屉访问。不依赖任何 hover-only 信息。

### 17.6 可读性与系统适配

- 移动端基础字号 14px，命令 / 编制树节点 ≥13px，按钮与选择框 `min-height:44px`；
- `viewport-fit=cover` + `env(safe-area-inset-*)` 适配刘海屏与底部安全区；`theme-color`、iOS / Android 添加到主屏元信息；
- 横屏与 ≤420px 各有独立媒体查询；`overflow-x` 工具栏横向可滑动，避免三级比例尺按钮被压扁；
- 单文件、零外部依赖的既有优势保留：手机离线打开 `index.html` 即可玩。

### 17.7 验收

`node tests/smoke_test.js` **ALL PASS**（v0.8 新增 15 项断言）：三档媒体查询、触控目标与安全区、移动端 DOM、Pointer 事件绑定、抽屉开合与互斥、全屏地图切换、精简状态条与浮动控件渲染、窄屏容器下 viewBox 按比例自适应且面积守恒（实测 536.7×715.5、面积 384000 不变）、触屏按世界坐标落格含子格 / 微格、单指拖拽被识别、桌面 `viewBox 0 0 800 480` 与三栏布局保持不变。另用无头 Chrome 以 **390×844 手机竖屏、834×1194 平板竖屏**实际截图复核首屏、命令抽屉与全屏地图三种状态，据此修正了底部主按钮被挤出屏幕、地图变形、全屏浮动按钮不可见、图例挤占地图等问题。端到端推演与全部既有评估分档不变。

## 18. v0.9：从静态快照到四维态势图（路线 / 战斗效果 / 战术战略表现）

用户要求"统筹全局"地设计行军路线、战斗效果、战术战略效果的表现形式。核查后的判断是：**问题不在缺几种特效，而在整个表现层只表达了一个维度**。

### 18.1 问题定义：一张"当下"的图，讲不出一场战斗

v0.8 的 `renderAll()` 是一张**静态快照**——它精确回答"现在谁在哪里"，但一场推演真正需要读懂的是五件事：

| 维度 | 玩家要问的 | v0.8 的答案 |
|---|---|---|
| 空间 | 谁在哪、地形如何 | 地图（完整） |
| 过程 | 部队从哪来、往哪去 | 无，只能靠记忆 |
| 事件 | 哪里交火、强度与结果 | 文字战报 |
| 因果 | 为什么这个结果（集中、合围、近迫、要点） | 评分卡与文字 |
| 时间 | 上一时段发生了什么、如何复盘 | 无 |

把后四维全塞进文字战报，结果是"地图很干净但读不懂战斗"。因此本版不逐个加特效，而是先建立**统一的表现框架**：所有可视化数据来自一条只读事件流，由「**图层 × 时间轴**」两个控制维度统一调度。

### 18.2 四条设计原则

1. **表现层严格只读（旁路记录）**：`S.fx` 由引擎在结算时旁路写入，任何渲染函数都不回写 `S`，不参与兵力、士气、胜负、评分的计算。删掉整个 FX 层，游戏逻辑与既有分数完全不变。这是能与 v0.4–v0.8 的复杂引擎共存的前提。
2. **军事标绘符号语言，而非更多颜色**：进攻轴线（粗实线箭头）、计划路线（虚线）、已执行轨迹（渐隐虚线）、敌动向（红虚线）、合围圈（虚线椭圆）、主攻楔形、牵制阻断、预备队环、固守盾、爆星（交火）、斜线圆（压制）、短横（交通壕）、叉框（歼敌）——用**形状与线型**编码语义，颜色只作阵营辅助，兼顾色觉障碍与投影偏色。形状编码是显示约定，不宣称还原某一年的制式军标。
3. **信息丰富 ≠ 全要素同屏**：延续 §14 的分级综合思想。四组新图层按 LOD 自动分级（师级只给路线骨架与战略方向、团级加战斗效果与战术符号、营连级全开），每个图层可独立开关；**地图上只放符号，数值统一进「态势摘要卡」**，避免标签与 §16 的单位标号牌争空间。
4. **动画克制且可降级**：动画只承担两个语义——`fx-flow` 表达方向、`fx-pop`/`fx-float` 表达瞬时事件；`fx-pulse` 表达持续状态。不引入发光、模糊、粒子，避免流式渲染闪烁；`prefers-reduced-motion` 与移动端（≤900px）静态降级，一键动画开关可完全关闭。

### 18.3 数据层：一条事件流 + 逐时段快照

```
S.fx = { events:[], trails:{}, history:[], viewTurn:null, playTimer:null, animate:true }

fxPush(type,x,y,extra)   // 旁路埋点；只读追加，无返回值、不读结果
fxSnapshot()             // endTurn 末尾：轨迹 + 事件 + 单位/敌位置 + 战果 + 战略分
fxEvents() / fxTrails()  // 实时取当前值；复盘按 viewTurn 取历史 / 截断轨迹
```

埋点共 29 处，覆盖 `ourActions`（机动、侦察、架线、喊话、弃守、工事、近迫、炮火、政治、休整、待机、围而不打）、`enemyActions`（增援抵达、敌机动、突破告警、漏网）、`resolveCombat`（交火、合围）、`killEnemy`（歼敌）、`supportPhase`、`randomEvents`、`subPhase`（连战术动作）。事件字段含 `t / type / x,y` 与各自的数值载荷（如 `dmgE / dmgU / ratio / enc / allies / cap`）。

**单一事实源**：合围圈复用引擎的 `encircled()` 判定；交通线控制带复用 `updateObjectives()` 的同一判定；进攻轴线读当前 `u.order`；计划路线读 `S.orders / S.subOrders`。因此图上不会出现与结算不一致的"第二个事实"。

**复盘语义隔离**：复盘时只显示该时段的事件与截至该时段的轨迹；由**实时状态派生**的要素（进攻轴线、敌动向、控制带、合围圈、营任务符号、炮火压制区）全部隐藏，避免把"现在的态势"误读成"当时的态势"。单位标号牌仍显示实时位置，界面明确标注复盘时段。

### 18.4 四组图层

| 图层 | 内容 | LOD |
|---|---|---|
| **A 行军路线 `route`** | ①计划路线：待传达命令的虚线箭头 + 生效时段（师级）；②已执行轨迹：最近 7 时段渐隐折线，越旧越淡，末端方向箭头（只画团 / 直属 / 敌主棋子，不画 117 个下级实体）；③进攻轴线：攻击 / 穿插 / 夜袭等当前命令的粗金箭头；④敌预期动向：`ai.goal` 红虚线 | `[1,1,1]` |
| **B 战斗效果 `combat`** | 交火爆星（按歼敌量 1 / 1.2 / 1.5 三档）、带斜纹的炮火压制圈与倒计时、向敌延伸的交通壕短划、歼敌 / 漏网事件符号、上飘淡出的浮动战果数字、空袭符号；师级仅保留关键事件 | `[1,1,1]` |
| **C 战术态势 `tactic`** | 合围圈（虚线椭圆 + "合围"）、营任务符号（主攻楔 / 牵制阻断 / 预备队环 / 固守盾）、营连级连战术动作图标（镐 / 星 / 眼 / 喇叭 / 盾） | `[0,1,1]` |
| **D 战略态势 `strategy`** | 交通线控制带（我方实控的铁路 / 公路节点）、战役意图大空心箭头（依据各剧本 `intent` 与真实电文，标注为方针示意而非精确坐标） | `[1,0,0]` |

所有符号尺寸乘 `u = 1/k`（§14 已建立的尺度解耦），放大 9 倍后屏幕上大小不变；箭头由 `fxArrow()` 统一生成（`<path>` 画三角，保持 `polygon=0` 的"无 2.5D 立体块"验收语义）。

### 18.5 易理解性的五项具体措施

1. **符号上地图、数值进卡片**：初版实图显示，事件文字标签与 §16 的敌我标号牌在团级视图严重互压。改为地图只保留符号与浮动战果数字，把「交火 5 处 · 歼 1485 / 我 106」这类聚合数值放进地图下方的**态势摘要卡**；摘要卡同时给出六条战略进度（歼敌、伤亡比、局部集中、战斗准备、交通线控制、战役分）。
2. **尺寸与透明度收敛**：压制圈半径 `0.44 CW → 0.30 CW`、合围圈 `0.86 → 0.62` 格，描边与填充透明度下调；营任务符号缩小并降至 0.55 不透明度。初版那个罩住整片敌我标号牌的巨大金色椭圆，实图复核后已消除。
3. **LOD + 手动开关**：默认按比例尺给"决策所需的最小信息"，玩家可单独开 / 关四层，一键「自动分级」复位。
4. **复盘时间轴**：工具栏「◀ 上一时段 / ▶ 回放 / 下一时段 ▶ / ⟲ 实时 / 动画开关」，按逐时段快照步进；自动播放在无定时器环境下自动降级为单步。配合"第 N 时段"标签，形成兵棋的 AAR（after action review，战后复盘）。
5. **不打断既有交互**：所有新图层 `pointer-events="none"`，点击仍走 `onCell()` / 微格热区；命令下达、选中、部署流程不受缩放与复盘影响。

### 18.7 边界

## 19. v1.0：从网页表单到指挥所作战台（控制面板的游戏化）

用户的问题不是"把面板换个颜色"，而是：**整套控制面板的载体是网页表单**——`h3` 标题 + 按钮网格 + `<select>` + 纯文字列表。它精确、但读起来像后台配置页，不像在指挥一场战役。

### 19.1 诊断：列表丢失了什么

| 面板 | v0.9 的形态 | 缺失的游戏信息 |
|---|---|---|
| 顶栏 | 7 枚文字 chip | 状态灯、进度感、指挥所身份 |
| 编制树 | 缩进文字行 | 单位类型、兵力比例、在编状态 |
| 单位详情 | 键值表 + 细进度条 | 仪表刻度、单位牌层级 |
| 命令面板 | 纯文字按钮网格 | 命令类别、代价、目标需求、按下反馈 |
| 通信方式 | 原生 `<select>` | 设备的物理感、延迟与可靠性读数 |
| 传达队列 | 一行行文字 | "电报回执"的时间与层级 |
| 敌情通报 | 文本行 | 兵力条、装备标签、威胁灯 |
| 战报 | 纯文本列表 | 时间戳、分类色带、纸带质感 |
| 当前指示 | 一段长文字 | 关键数值的仪表化 |

共同问题：**所有信息以同一种权重、同一种字号、同一种容器呈现**，玩家得逐行读文字才能找到"作业量还剩几点""这个命令要不要选目标"。游戏 HUD 的做法是让**状态一眼可见、动作一眼可点、代价一眼可比较**。

### 19.2 设计隐喻与硬约束

统一隐喻：**指挥所作战台**——编号的仪表模块、黄铜铭牌、切角指令键、电台按键、电报回执、纸带战报、带密级戳记的作战命令夹。

四条硬约束（保证改造不伤及引擎）：

1. **所有 id、`onclick`、innerHTML 文案保持不变**：`renderXxx()` 仍按原 id 写入，既有 100+ 项断言不因换皮而失效。
2. **只换载体，不换数据**：命令代价、延迟、可靠性、伤亡、评分都来自原有常量与状态；新出现的图标、编号、色条只是呈现层常量（`CMD_GLYPH / CMD_FAMILY / COMM_ICON`）。
3. **桌面三栏 + 移动端抽屉的布局契约不变**：`grid-template-columns:274px minmax(520px,1fr) 318px`、三档媒体查询、`≥44px` 触控目标、Pointer 手势全部保留。
4. **零外部资源**：无字体 / CDN / 图标库 / 图片，全部 CSS 与 Unicode 几何字符；`prefers-reduced-motion` 降级；动画只用于按下反馈。

### 19.3 组件映射

| 顶栏 | 指挥所铭牌 + 带指示灯的仪表胶囊 + 推演进度条 | 剧本 / 时段 / 昼夜 / 敌情 / 信任 / 战役意图 / 进度 |

## 20. v1.1：情报不对称与对等敌方指挥

用户提出两个相互关联的根本问题：① **v1.0 把敌方 `ai.goal` 直接画成红虚线"敌预期动向"，等于把敌人的决心摊给玩家看**；② 敌方只有 `advance` / `hold` 两个固定动作，"很傻"，没有军事指挥能力。这两件事必须一起解决：**隐藏敌情才有指挥乐趣，而对手必须真的会打仗，隐藏才有意义**。

### 20.1 史料依据（详见 SOURCES.md §19）

### 20.2 现代游戏设计依据

- **Fog of War（战争迷雾）**：把"地理与敌情的知识"变成需要主动获取的资源；个体迷雾 + 回归迷雾让持续侦察有价值；地形可见而单位位置隐藏是 RTS 常用折中。本作采用**逐单位侦知等级 + 情报过时**，地形始终可见（真实地图已是静态底图）。
- **信息不对称产生有意义决策**：完全信息下空间策略退化，"侦察投入 / 风险承担"成为真正的选择。
- **AI 不得窥屏**：「AI 忽略迷雾、直接知道玩家位置，一旦被玩家察觉就摧毁信任」。因此敌方决策**只能读 `foeEstimate()` 的不完整估计**，不能直接读 `S.pieces` 真实坐标。
- **Utility AI（效用评分）**：给每个可选动作按当前态势打 0–1 分取最高，比状态机更能应对复杂局面；需加**行为惯性、冷却与少量随机**避免抖动与被套路化。
- **OODA 循环**（观察 / 判断 / 决心 / 行动）与「对手应可击败、可读但不可预测」：AI 的目标不是最优，而是让玩家既看得懂它做了什么、又猜不到下一步。

### 20.3 情报模型（`S.foeIntel` / `S.foeView`）

**每支敌军一份独立侦知档案**，不再用一个全局 `S.intel` 决定一切：

| 等级 | 名称 | 玩家看到 |
|---|---|---|
| 0 | 未侦知 | 地图、路线、标号牌、边缘指示**完全不显示**；敌情通报合并为"另有 N 处敌情未侦知" |
| 1 | 有迹象 | 最后确认位置画"敌情？"虚影轮廓，无番号、无兵力 |
| 2 | 概略 | 示意番号 + 兵力区间（约百人取整）+ **最后确认位置与时段**；轨迹、接触线、精确读数仍不可见 |
| 3 | 确实 | 精确标号牌、兵力、装备、工事、接触线与已发生的行军轨迹 |

- **情报来源**：接触发现（相邻自动升 3）、侦察连 / 连级侦察动作、忍耐待机观察、审俘（歼敌后供述）、群众带路、上级来电通报、炮火准备的火力暴露。
- **情报过时**：未被本时段刷新的档案累计 2 时段降一级，来源改标"情报过时"；`foeReportPos()` 返回**最后确认位置**而非真实位置，敌人机动后旧标记留在原地。玩家据此下令扑空时，战报给出「扑空 · 建议重新侦察」。
- **敌方对我方同样有迷雾**：`S.foeView` 逐团记录敌方认知等级，靠接触与侦察任务提升；`foeEstimate()` 在概略级返回带偏移的估计坐标，在迹象级只返回旧通报方向，**绝不返回真实位置**。我方主动开火会 `ourFireExpose()` 暴露阵地。

### 20.4 敌方指挥模型（OPFOR C2）

每时段 `foeCommandPhase()` 走完整 OODA：

```
Observe   refreshContactIntel() / ourFireExpose() / foeScout()
Orient    foeContext(): 用 foeEstimate 估计的兵力比、地形、己方士气弹药、友邻威胁、是否被合围
Decide    foeUtility() 对 10 类任务评分（+ 随机 0.10 + 惯性 0.09 + 连任降权 0.50）
          → 决心进 S.foeOrders 队列，延迟 = 剧本 foeC2.delay + 协同失败附加
Deliver   foeDeliver(): 到达才生效；协同判定失败再延一时段
Act       foeExecute(): 机动 / 筑垒 / 火力准备 / 侦察 / 增援靠拢 / 有序转进
```

**十类任务**（与我方对称）：

| 任务 | 攻 / 防系数 | 对应能力 |
|---|---|---|
| `main` 主攻突击 | 1.30 / 0.95 | 集中兵力突击 |
| `support` 助攻协同 | 1.12 / 1.00 | 多方向策应 |
| `pin` 牵制 | 0.85 / 1.08 | 以一部牵制我主力 |
| `flank` 迂回穿插 | 1.18 / 0.92 | 绕开正面、切交通线 |
| `fortify` 固守筑垒 | 0.90 / 1.35 | 逐时段提升工事，士气回升 |
| `prep` 火力准备 | 1.10 / 1.00 | 覆盖我集结格、削工事 |
| `ambush` 设伏反冲击 | 1.25 / 1.05 | 我攻击后反制 |
| `assist` 增援友邻 | 1.00 / 1.02 | 受威胁友军靠拢；协同失败则象征性推进（"尖锥战术"） |
| `scout` 侦察搜索 | 0.80 / 1.00 | 提升敌方对我方的认知 |
| `withdraw` 转进突围 | 0.70 / 1.10 | 向后方机动，连续脱离接触才判有序转进 |

**剧本指挥特性**（`foeC2`）：孟良崮 `delay 1 / cohesion .58`（情报不灵、推进谨慎）、塔山 `delay 1 / cohesion .72`（统一指挥、海空协同）、徐蚌 `delay 2 / cohesion .48`（派系掣肘、增援迟缓）。

### 21.4 数据结构与坐标纪律

```text
CARTO[gk] = [{ n, t, lv, lon, lat, e?, src, exact? }, ...]
CARTO_KIND = { town, peak, height, relief, river, road, field, wood }   // 四色图式
cartoVisible(gk,z) = CARTO[gk].filter(o => o.lv <= z)
cartoRank(o)       = (4-lv)*10 + (有高程?4:0) + (实测?1:0)
```

- `t` 决定符号与颜色：居民地浅米、山与崮棕、编号高地白、地貌部位棕虚、水系蓝斜体、道路米色、工事橙、植被绿。对应军用地形图黑 / 蓝 / 绿 / 棕四色语义。

## 23. v1.3.1 开场页与覆盖层响应式修复（2026-11-16）

### 23.1 问题与根因

用户提供的截图显示主页介绍在约 1100×630 视口下底部操作说明被裁、剧目卡片与按钮拥挤。逐项核查 CSS 与 `showStart()` 后确认四个根因：

1. `.ov{display:flex;align-items:center}` —— 内容高于视口时 flex 居中会把**顶部推到视口外**，用户滚不到被裁的标题与开头。
2. 桌面端 `.ovcard` 只有 `max-width`，没有高度上限与内部滚动；只有 `@media(max-width:900px)` 才设 `max-height:86vh;overflow:auto`，桌面反而失控。
3. 开场介绍是约 20 余行密集小字构成的一整块 `<div class="facts">`，无折叠、无分区；底部操作说明又是一长串 `<div class="sub">`，把卡片和按钮整体顶出视口。
4. `.scs` 固定 `repeat(3,1fr)`，移动端三卡挤压；副标题仍写 v1.1，与实际功能不符。

### 23.2 覆盖层通用修复（4 个 overlay 同时受益）

```css
.ov{display:flex;align-items:flex-start;justify-content:center;
    padding:clamp(10px,3vh,28px) clamp(10px,3vw,28px);
    overflow-y:auto;overscroll-behavior:contain}
.ovcard{max-width:min(820px,100%);width:100%;margin:auto}
```

`align-items:flex-start` + `margin:auto` 是标准解法：内容小于容器时 `margin:auto` 均分剩余空间实现居中，内容大于容器时 auto margin 归零、卡片贴顶且 `.ov` 可滚动，**顶部永不被裁**。`overscroll-behavior:contain` 防止滚动穿透到主界面。`showBrief()` / `showLore()` / `showResult()` 共用该容器，同类问题一并消除。

### 23.3 开场命令夹三段式

`showStart()` 重构为 `.ovcard.startcard > .ovhead + .ovbody + .ovfoot`：

- `.ovhead`（`flex:none`）：标题 + 更新到 v1.3 的副标题。
- `.ovbody`（`flex:1 1 auto;min-height:0;overflow-y:auto`）：**3 段核心介绍**（你是师长 / 上级不遥制 / 四级地图三级指挥）+ `<details class="startmore">` 折叠的完整玩法与版本沿革 + 三个剧目卡片。
- `.ovfoot`（`flex:none`）：两个按钮 + 精简到 3 行的操作条。

`.startcard` 设 `max-height:calc(100dvh - clamp(20px,6vh,56px))`（恰好减去 `.ov` 上下 padding）与 `overflow:hidden`，因此**标题和开始按钮始终可见**，只有中间介绍滚动。首屏 `<br>` 从 20+ 降到 9。

### 23.4 响应式细则

- `.scs` 改 `repeat(auto-fit,minmax(190px,1fr))`；`@media(max-width:620px)` 下单列、按钮 `flex:1 1 100%` 整行且 `min-height:44px`。
- `@media(max-width:900px)` 下卡片 padding 收紧、`details summary` 达 44px 触控目标。
- 所有依赖视口高度的规则（`.left/.right`、两栏 `.right`、`.msheet`、`.msheet-open`、`.startcard`）**先写 `vh` 再写 `dvh` 回退**，移动端地址栏伸缩不再改变可用高度。

### 23.5 验证与限制

`node tests/smoke_test.js` **ALL PASS，267 项断言 / 0 失败**，v1.3.1 新增 10 项：覆盖层滚动规则、三段式结构、副标题版本、卡片自适应与窄屏单列、dvh 回退、4 个 overlay 共用容器、开场 DOM 层级、剧目卡与按钮、折叠说明与首屏精简、切换剧目刷新。

**限制**：本环境无头浏览器进程无法常驻（CLI `--screenshot`、CDP 调试端口均多次失败），因此**没有像素级截图复核**；改用源码规则 + DOM 结构断言，并在预览面板提供可交互页面由用户目视确认。这是验证覆盖范围的如实说明，不代表已完成浏览器实测。

### 23.6 边界

## 24. v1.4 地图交互现代化（2026-11-16）

### 24.1 问题定义

旧交互是「表单式」：左侧选单位 → 右侧选命令按钮 → 回到地图点目标 → 结束时段。对比现代战略 / RTS 游戏，缺四类高频动作：右键快捷下令、命令热键、目标预览、全图导航。此外核查中发现一处真实信息泄漏（见 24.2）。

范围：**只改输入方式与界面反馈**，命令语义、通信延迟、作业量、结算、评分、敌方 AI 与迷雾全部沿用既有实现。非目标：拖拽部署（仍走「调整阵位」按钮）、多选单位群令、命令撤销栈。

### 24.2 信息泄漏修复（必须先做）

`onCell()` 原实现用 `S.enemies.find(e => e.x===x && e.y===y)` 识别点击目标并输出番号、装备与工事等级——这是**敌方真实坐标**，点击未侦知敌所在格即绕开 v1.1 迷雾。修复：

- 新增统一入口 `foeAtCell(x,y)`：`foeSighted()` 过滤 + `foeReportPos()` 最后确认位置；
- `onCell()` 按 `foeLvl` 分级输出：确实＝番号 / 装备 / 工事，概略＝兵力区间，有迹象＝「当面之敌」，并标注情报过时时段；
- 右键菜单、悬停预览、小地图**全部复用该入口**，不另设事实源。

自动化断言直接点击未侦知敌真实坐标，验证日志不含其番号、装备与工事等级。

### 24.3 右键上下文命令

`m.oncontextmenu` 阻止浏览器默认菜单，按目标类型动态生成菜单：

### 24.9 v1.4.1 选点误触修正

用户反馈「地图选点容易全选」。核查后定位两个独立根因：

1. **桌面端文本被整片选中**：`.map{user-select:none}` 原先只写在 `@media(max-width:900px)` 内，桌面端点击 / 拖地图时 SVG 内的地名、番号、高程点等 `<text>` 会触发浏览器原生拖选，出现整片蓝色高亮，视觉上就是「全选」。修复：把 `user-select:none` / `-webkit-user-select:none` / `-webkit-touch-callout:none` 统一到所有视口的 `.map`，并显式覆盖 `.geosvg text / title / .tile` 与 `::selection`（透明背景）；鼠标 `pointerdown` 时额外 `preventDefault()` 阻断原生拖选，但保留 `click` 与 Pointer 手势状态机。
2. **系统快捷键误下令**：`setupKeys()` 未检查修饰键，`Ctrl+A` / `Cmd+A`（浏览器全选）的 `ev.key==='a'` 会命中 A＝进攻热键。修复：在键位分派前 `if(ev.ctrlKey||ev.metaKey||ev.altKey) return;`，系统快捷键完全交还浏览器；普通 `A` 仍进入待指定模式。

新增 5 项断言：全局不可选中规则、修饰键过滤、`Ctrl+A` 不误下令且不 `preventDefault`、普通 `A` 仍生效、`pointerdown` 阻选且手势状态机正常、修复后命令仍可下达。`node tests/smoke_test.js` **ALL PASS，287 项断言 / 0 失败**。纯输入层修复，不改史实、规则、结算、评分、AI 与迷雾。
