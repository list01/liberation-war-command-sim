# 《解放战争》师级指挥模拟器

以解放战争**宏观史实、真实上级电文与真实战区地理**为依据的网页兵棋：玩家任师长，接到上级的方针与意图后机断专行，在按真实经纬度投影、标注真实地名 / 河流 / 铁路 / 公路的战场上，指挥师、团、连、班及直属分队遂行作战任务。

## 项目信息

- 项目 ID：`liberation-war-command-sim`
- 类型：`software`｜状态：active（**v1.4.1 · 现代战略游戏地图交互（含选点误触修复）**）
- 创建：2026-11-15｜最近更新：2026-11-16
- 技术栈：单文件 HTML + 原生 JavaScript / CSS；**主游戏零外部依赖、可离线双击运行**
- 纳管规范：`D:/.workbuddy/policies/WORKSPACE_HYGIENE.md`

## 快速开始

1. 双击 `src/index.html`（或浏览器打开）→ 选择剧本 → 「受领战斗命令，开始推演」。
2. 左侧编制树 / 中部地图点选单位 → 右侧选择命令与通信方式 → 点击地图格指定目标 → 「结束本时段 / 推演」。
3. 顶栏可随时：**战局背景 / 电文原件**、**战斗命令 / 编制**、**上报战况**、**收兵 / 结束推演**、**真实地理对照**。
4. 每时段师部有 **4 点参谋作业量**；命令按通信方式与指挥层级产生传达延迟，可能中断。建议每 2–3 时段「上报战况」一次。
5. 终局给出多结局、九维战略分、「十大军事原则评分卡」与「本级决心记录」复盘。
6. **地图分四级看，部队也分三级指挥**：工具栏切「师级全景 / 团级战术 / 营级部署 / 连级战斗」（等效 1:20 万 / 1:5 万 / 1:2.5 万 / 1:1 万军用地形图），滚轮或 ＋/－ 缩放、按住拖动平移、图层可独立开关。放大到团级，每个团解聚为 3 个营；再放大到营 / 连级，营解聚为 3 个连、连辖 3 个班。**地名随级别展开**：团级标县城、山名与编号高地；营级增标村庄、鞍部、冲沟与渡涉点；连级增标崮顶、陡崖、凹地与阵地工事。
7. **指挥团以下单位**：点地图上的营 / 连 / 班或展开编制树选中它 → 右侧命令面板自动切换为该级命令（营 6 类任务编成、连 13 类战术动作、班 5 类专门小组）→ 选通信方式 → 下达。营命令耗 1 点作业量、传达延迟 +1 时段；连 / 班耗 2 点、+2 时段。可「调整阵位」把单位放到具体子格 / 微格要点，或「派出」为独立分队。
8. **一键视图与快捷键**：图层栏可切「战术 / 地形 / 情报」预设或「自动分级」；视图键 `1–4` 切级、`＋/－` 缩放、`F/E/C` 定位、`[ ]` 复盘、`L` 实时、`0` 复位。点击「地名」面板的分级条目可定位并查看史料依据；悬停地图格可看阵地工事、本格地名与待传达命令。
9. **地图直接指挥（v1.4）**：选中我方单位后**右键地图**弹快捷命令——空格给「机动 / 侦察 / 工事 / 待命」，已侦知敌给「进攻 / 穿插 / 佯动 / 近迫 / 炮火」；`Shift+右键` 改用有线电话。也可直接按 `A` 进攻、`M` 机动、`I` 穿插、`R` 侦察、`T` 近迫、`H` 工事、`S` 待命，再点地图指定目标；`Esc` 一次取消全部待令。悬停显示目标框与意图箭头，右下**小地图**点击即可跳转。

运行测试与生成静态快照：

```bash
node tests/smoke_test.js          # 端到端冒烟 / 合规 / 分级地志断言
node tools/render_preview.js      # 生成 out/map-{regiment,battalion,company}.html
```

可直接打开某一级视图（只改视图，不改史实 / 规则 / 情报）：`src/index.html?sc=0&z=2&cx=375&cy=310`。`out/map-*.html` 是从同一渲染管线导出的自包含静态快照，便于对照四级注记密度。

`src/geography.html` 是可选的**真实地图对照页**：使用腾讯地图 GL JS（合规白名单、默认代理模式、前端零密钥、GCJ-02）核对历史地名与交通线。需在 WorkBuddy 运行时或联网环境打开；离线时自动降级为可查阅的地名表，主游戏不受影响。

## v1.4：现代战略游戏地图交互（现行）

用户要求「优化地图的交互方式，使在地图上的指挥操作更加符合现代的战略游戏交互方式」。核查后确认旧流程是表单式（选单位 → 选命令按钮 → 回地图点目标），缺右键快捷下令、命令热键、目标预览与全图导航；同时发现并修复一处真实的信息泄漏。

- **修复信息泄漏（前置）**：`onCell()` 原先用敌方**真实坐标**识别点击目标并输出番号 / 装备 / 工事，点未侦知敌所在格即绕开迷雾。现统一经 `foeAtCell()`（`foeSighted()` + `foeReportPos()`），按侦知等级分级输出；右键菜单、悬停预览、小地图全部复用该入口。
- **右键上下文命令**：按目标动态给命令——空格＝机动 / 侦察 / 工事 / 待命；已侦知敌＝进攻 / 穿插 / 佯动 / 近迫 / 炮火；选中营连班＝该级任务表；未选中＝「先在编制树选单位」。`Shift+右键` 改用有线电话。所有命令走既有 `issueOrder()` / `issueSubOrder()`。
- **命令热键**：`A` 进攻、`M` 机动、`I` 穿插、`R` 侦察、`T` 近迫、`H` 工事、`S` 待命；需目标者进入待指定模式，原地命令直接下达；`Esc` 一次取消师级待令 / 下级待令 / 阵位调整 / 右键菜单。`F` 保留定位选中。
- **悬停预览**：目标格高亮框 + 从选中单位出发的虚线意图箭头 + 已侦知敌标记；未侦知只显示地形指向，不暴露敌名；只更新预览层，不整图重绘。
- **小地图导航**：新增 `minimap` 图层（团 / 营 / 连级显示），11×7 高程缩略 + 我方点 + **已侦知敌点** + 视口框，点击跳转；师级全景自动隐藏。

`node tests/smoke_test.js` **ALL PASS，287 项断言 / 0 失败**（v1.4 新增 15 项，v1.4.1 新增 5 项）。

**v1.4.1 选点误触修正**：`.map` 的 `user-select:none` 原先只写在 ≤900px 媒体查询里，桌面端按住地图拖选会把地名、番号、高程点整片蓝选；命令热键也未过滤 `Ctrl/Meta/Alt`，`Ctrl+A` 会误触发进攻。现已把不可选中约束统一到所有视口（含 `text/title/tile` 与 `::selection` 透明），系统快捷键全部交还浏览器，鼠标按下阻断原生拖选而 click 与手势照常。设计推演见 `docs/DESIGN.md` §24，交互设计依据与非史实边界见 `docs/SOURCES.md` §22。

## v1.3.1：开场页与覆盖层响应式修复（保留作沿革）

用户反馈：主页介绍在电脑端显示不完整——底部操作说明被视口裁掉、剧目卡片与按钮拥挤，移动端必然更差。

- **根因**：`.ov` 用 `align-items:center`，内容超高时顶部被裁且滚不到；桌面端 `.ovcard` 没有高度上限和内部滚动；开场介绍是一整块 20 余行密集小字；`.scs` 固定三列；副标题还残留 v1.1。
- **修复**：覆盖层改 `align-items:flex-start` + `.ovcard{margin:auto}` + `.ov{overflow-y:auto;overscroll-behavior:contain}`——超高内容始终可从顶部滚动、不穿透到主界面；开场命令夹改**三段式** `.ovhead`（标题 / v1.3 副标题）/ `.ovbody`（长介绍独占滚动区）/ `.ovfoot`（按钮 + 精简操作条），标题与按钮常驻；20 余行说明收敛为 **3 段核心 + `<details>` 折叠项**（首屏换行从 20+ 降到 9）；剧目卡片 `auto-fit,minmax(190px,1fr)`，≤620px 单列且按钮整行（≥44px 触控）；所有 `vh` 高度规则补 `dvh` 回退，移动端地址栏伸缩不变形。`showBrief / showLore / showResult` 沿用同一可滚动容器。
- **验证**：`node tests/smoke_test.js` **ALL PASS，267 项断言 / 0 失败**（新增 10 项布局与开场结构断言）。真实浏览器截图在本环境无法产出（无头浏览器进程不常驻，多次尝试均失败），已改为源码规则 + DOM 结构断言，并在预览面板提供可交互页面供目视确认。

## v1.1：情报不对称与对等敌方指挥（保留作沿革）

用户指出：v1.0 把敌方 `ai.goal` 画成红虚线"敌预期动向"，等于把敌人的决心摊给玩家；且敌方只有 `advance/hold` 两个固定动作，不像有指挥能力。本版一并解决。

- **敌方决心永久隐藏**：删除敌动向箭头；`e.task` / `e.goal` / `S.foeOrders` 从不进入任何可见面板。敌方轨迹只有"确实情报"时才显示（那是已发生的事实，不是意图）。
- **逐单位战争迷雾**：每支敌军有「未侦知 / 有迹象 / 概略 / 确实」四档档案。未侦知完全不画；迹象只画"敌情？"虚影；概略给兵力区间与**最后确认位置**；确实才给精确标号、兵力与接触线。情报会过时降级，敌人机动后旧标记留在原地，玩家据此扑空会得到「建议重新侦察」提示。
- **情报来源**：接触、侦察连 / 连级侦察、忍耐待机、审俘、群众带路、上级来电、炮火火力暴露；另有 `S.foeView` 记录敌方对我方的不完整认知——**敌方不窥屏**，决策只读带误差的 `foeEstimate()`。

## v0.4：基于开放高程数据的二维真实地形图（保留作沿革）

用户反馈 2.5D 效果不好，本版**彻底移除等距立体渲染**，改为二维平面 + 等高线的真实地形图。

- **数据来源**：`aster30m` = NASA/METI **ASTER GDEM**（约 30 m 全球开放 DEM），经 Open Topo Data 公共高程 API 只取**数值**，不是地图瓦片 / 底图服务。原计划 `srtm30m`（SRTMGL1 v003），采集时该端点持续超时，故改用同为 NASA 公开约 30 m 的 ASTER GDEM。
- **采集与重建**：每战区按包围盒采 **12×8 = 96 个实测控制点**（16 点/请求、断点续采）；实测高程 孟良崮 93–834 m、塔山 0–417 m、徐蚌 5–112 m，与史料记载吻合。控制点双线性加密到 **60×36 绘制网格**并轻度平滑。
- **诚实标注**：控制点是实测值，60×36 网格是**插值产物**（元数据写明 "NOT a full-resolution DEM"），不代表 30 m 原始分辨率；现代 DEM 只重建自然地形骨架，1948 年聚落 / 道路 / 水系仍以军史史料为准。
- **二维渲染**：8 级高程分级晕渲（约 2065 个色块）+ **marching squares 等高线**（间隔自适应 100 / 50 / 10 m，共 7 / 8 / 10 层，主曲线加粗标注高程）；真实河流、铁路、公路与地名按像素级折线 / 标签叠加；单位回归平面圆 / 菱形棋子；18×11 平面透明热区，悬停显示地名、类型、**实测高程**与敌我兵力。
- **地形判定**：不再程序生成，`buildTerrain()` 由真实高程派生山地 / 丘陵 / 树林 / 平原，再叠加真实水系、交通线与城镇。
- **合规**：主游戏离线自绘 SVG、无外部脚本、不使用任何第三方地图瓦片；在线对照页仍只用腾讯地图白名单服务。

数据可复现：`python data/fetch_elevation.py --max-batches 8`（重复运行至 COMPLETE）→ `python data/embed_elevation.py`。详见 `docs/SOURCES.md` §12、`docs/DESIGN.md` §13。

史实依据：1947-05-12 中央军委电「**究打何路最好，由你们当机决策，立付施行，我们不遥制**」；以及「在此方针下，由你们**机断专行，不要事事请示**……但将战况及意见每日或每两日或每三日报告一次」。

- 取消脚本化目标（不再要求占领指定格子/守固定回合数）。上级只给**方针 + 战役意图 + 约束 + 时限**。

- 胜负改为开放式九维评估：歼敌量、伤亡比、局部优势、合围、准备程度、**实际控制的真实交通线节点数**、决心多样性、按期上报、代价；并保留 8 项十大军事原则评分卡与多结局。
- 「主动弃守」不扣分，对应《集中优势兵力》「可以允许放弃某些地方」；「上报战况」影响上级信任。

## 沿用的 v0.1 机制

- **编制沿革**：1948-11-01 前这一级称「旅」（隶属纵队，每旅 3 团），通令后「旅统改称师、纵队改称军」，军以下三三制。界面统一称「师」，剧本卡标注当时实际称谓；单位树完整到团—营—连—班，连/班可「派出」为独立分队。
- **指挥通信**：有线电话 / 电台暗语 / 司号 / 通信员 / 小喇叭，各自决定延迟、可靠性与适用层级；线路被炸断、敌机干扰会造成命令中断。依据「东总命令十分钟传到连」等史料。
- **史实战术**：近迫作业（削敌工事、抵消远战火力）、夜战近战、穿插分割、佯动、设伏、炮火准备、政治攻势。
- **支前与政治工作**：民工队决定全师弹药与伤员后送；立功运动 / 诉苦三查恢复士气；解放战士「随俘随补」。
- **敌方特征**：整编师旅编制下的美械 / 日械 / 国械差异，火力强而协同弱，增援可能迟疑。
